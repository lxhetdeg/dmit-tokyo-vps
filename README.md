## 测东京 VPS，先分清哪些数据有用

最常见的三件套是 Ping、Speedtest 跑分、硬盘读写。都有用，但都容易被单次结果带偏。

**Ping 值只反映你按下去的那一刻。** 白天 40ms、晚上 200ms 丢包 15% 的机器很常见。国内用户的真实体感差异基本都出在 20:00 到 23:00 这个区间，所以只测白天的测评参考价值有限。

**Speedtest 跑分测的是端口带宽，不是回国速度。** 本地东京节点跑出 900Mbps，不代表从上海拉文件也快。要判断回国速度，得看单线程下载和 TCP 握手延迟，而不是多线程跑分。

**回程路由比去程更值得看。** 去程是你发请求过去，回程是数据回来。网页加载、看视频、下载文件，感受最强的都是回程。很多商家宣传"日本 CN2 GIA"，实际只有去程走优化线路，回程走国际线路绕一圈，测一下回程立刻现形。

剩下三项经常被忽略，但踩坑都踩在这：

- **CPU 偷取率（steal）**：0% 说明宿主没在抢你的核；长期 5% 以上，说明这台机器超售了。
- **4K 随机读写**：顺序读写 1GB/s 很漂亮，数据库和网站跑的是 4K 小块。有测评里同类东京机器 4K 随机只有 1.6k/6.0k IOPS，这种跑 WordPress 就会拖。
- **IP 质量**：原生 IP 还是广播 IP，流媒体能解锁哪几个区，25 端口能不能用。做日区业务的话，这条比跑分重要。

## 东京线路的名字都挺好听，差别很实在

上面这些线路名，是选东京 VPS 时最容易被糊弄的地方：

| 线路 | 大致定位 | 典型表现 |
| --- | --- | --- |
| CN2 GIA（AS4809） | 中国电信顶级国际专线，双程优化 | 晚高峰抗拥堵能力最好，价格最贵 |
| AS9929 / AS10099 | 中国联通精品网 | 联通用户延迟和丢包表现稳定 |
| CMI（AS58453）/ CMIN2 | 中国移动国际出口，CMIN2 为升级版 | 移动用户友好，带宽给得大方 |
| SoftBank / NTT / IIJ | 日本本地运营商的国际线路 | 亚太互联好，对中国大陆不做专门优化 |

一条真正的"三网优化"东京线路，通常是回程按运营商各走一条最优路径：电信走 CN2 GIA、联通走 9929 或 10099、移动走 CMI。而去程再单独做一遍优化。宣传页上写 CN2 GIA 不等于全程 CN2 GIA，也不等于三网都优化过。

**一个常见误区**：觉得"日本离中国近，延迟天然低"。物理距离确实近，但路由不直连的话照样绕。有测评里的东京机器，电信回程经 Cogent 绕到美国圣何塞再回国，延迟直接 150ms 起；联通回程绕洛杉矶能到 270ms 以上。这种机器 ping 日本本地 2ms，ping 广州 150ms。

## 东京、香港、洛杉矶，差的是哪一档

| 机房 | 常见三网延迟区间 | 相对定位 |

| 香港 | 20–50ms | 体验最好，价格也最难接受 |
